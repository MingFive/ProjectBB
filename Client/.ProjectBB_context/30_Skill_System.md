# ProjectBB 技能系统

## 系统定位

技能系统执行攻击与能力，不依赖玩家操作。技能来源可以是基础碰撞、周期 Trait、撞墙触发、技能物或其他受限的派生技能。

复用 ARPG 的 SkillManager、SkillRunner、SkillConfig、SkillHitConfig 与 SkillLineConfig 的职责划分；具体源码尚未迁入，不承诺旧方法签名可用。

## 职责

- SkillManager：注册依赖、释放请求、冷却、Runner 生命周期、命中转发。
- SkillRunner：按战斗时钟执行时间线，触发模块并向外传递结果。
- Collision 检测：产生空间命中事实，不直接扣血。
- DamagePipeline：统一命中有效性与伤害编排，见 [70_Damage_Pipeline.md](70_Damage_Pipeline.md)。
- SkillObject：负责生成、运动、生命周期和调用技能，不自行实现伤害公式。
- View：播放技能表现，不能决定命中成立。

普通技能默认不停止小球运动，不要求角色朝向目标，不默认进入阻断移动的施法状态。控制移动必须有明确技能/运动规则。

## 释放与身份

设计采用单一结构化释放请求，承载来源、施法者、目标或锚点、方向、技能等级、会话与派生链身份。最终类型、字段和 API 在实现时确定，不新增大量参数重载。

实体、技能物、攻击实例使用会话内稳定身份。命中去重不能按子 Collider 或表现 GameObject 计数。

Trait 只交接触发事实与目标/锚点。索敌、范围、命中和伤害仍由技能侧执行。

## 基础碰撞攻击

球体接触事实生成 A→B 与 B→A 两个轻量命中请求，进入同一结算批次，复用 SkillManager 命中处理。

基础碰撞攻击可无动画、无完整时间线 Runner，但必须复用统一命中与承伤规则，不能直接扣 HP。批次和死亡规则见 70。

## 技能与技能物类型

2026-10-12 已确定物理分工；DEV-005 已实现并验证一种圆形直线查询弹道，其他类型待实施。普通大量弹道采用逻辑轨迹与主动形状扫掠；需要真实物理交互的投射物、实体分身和物理召唤物采用 Dynamic。两种方式共用稳定身份、命中归并、生命周期和承伤入口，同一对象不得由两套运动/命中来源重复裁决。当前限圆形弹道与双圆球目标，不一次实现所有形状和召唤物能力，详见 [35_Ball_Movement_And_Collision.md](35_Ball_Movement_And_Collision.md)。

实体阻挡、受击、攻击和感知范围分开表达；普通攻击命中不自动推挤，需要击退时向统一运动控制入口提交请求。多个子 Collider 命中归并到目标实体，穿透弹道与持续武器各自持有去重记录。高速查询必须覆盖移动目标交叉、墙边反弹与初始重叠，不能仅对目标当前姿态的一次 Cast 宣称完整连续检测。

| 类型 | 首版用途 | 命中规则 |
| --- | --- | --- |
| 瞬时范围技能 | 一拳超人爆发 | 一个攻击实例对同一目标一次 |
| 静态技能物 | 提莫蘑菇 | 触发独立命中技能；首次有效触发后消耗 |
| 环绕技能物 | 狂战士两把斧头 | 每把独立记录扫过与重复命中保护 |
| 接触维持技能 | 吸血鬼 | 在有效贴附期间按战斗时间周期结算 |

蘑菇生成锚点来自墙体碰撞位置与法线，向场内偏移；生成时校验边界，配置寿命、存量上限及撞墙触发保护。

斧头运动检测考虑相邻逻辑时刻之间的扫掠，必要时细分角度，不能仅离散检查终点。检测频率与伤害重复间隔是不同参数，不照搬旧持续检测 100ms 下限。

蘑菇接触免疫目标是否消耗、多个斧头同时命中的平衡规则，需要在该技能制作时明确；“有效触发”不得在代码中含糊解释。

## DEV-005 圆形高速弹道闭环

2026-10-13 Unity 编译及实际 Play Mode 集成通过，原始报告在 WorkspaceRoot/outputs/projectile_validation。

- BattleSession.TryLaunchProjectile 接收 CircleProjectileRequest：会话、来源实体、出生位置、速度、半径、寿命和伤害。默认半径 0.15 格、寿命 2 秒、伤害 10；验证按钮朝敌方当前位置发射，速度 80 格/秒，不追踪、不穿透、不反弹。
- CircleProjectileSystem 持有 128 个值类型槽位，容量满返回失败并累计诊断，不替换旧实例。非法请求、旧会话、未知/死亡来源、暂停/后台/结束状态拒绝释放；当前速度上限 10000 格/秒、寿命上限 60 秒是输入保护，不代表精度或性能承诺。
- 圆形轨迹主动扫掠相对运动，枚举两球各一次；排除自身、同阵营、死亡/待死亡目标。以稳定实体身份查询，不使用子 Collider 数量作为命中次数；当前没有多实体候选缓冲或组合受击形状。
- 首个合格敌方命中后消耗。免疫仍接受命中并消耗，但 HP 损失为零；初始重叠和相切可命中。撞墙或到期回收；墙与目标同刻时墙优先，寿命截止上的合法命中先于到期。
- 实例以会话 + 递增 AttackId 标识，复用槽位不复用身份。查询只记录候选，SkillManager.CaptureProjectile → DamagePipeline → CombatManager 完成承伤；死亡由结算器提交。DamageRequest.SourceKind 区分 Projectile 与 Collision，弹道的 ContactRound 为 0。
- 每个物理子步边界先球球互伤，再按弹道生成身份递增独立结算。每个后续请求重新校验来源/目标；不同弹道不共享同时伤害批次。结束、超时、释放清全部在途实例；重开清反馈和 View 池，不残留命中记录或来源引用。
- View 复用圆形 Sprite 节点、读取值快照及实际 HP 损失；提供“红方发射 / 蓝方发射”。DEV-006 已增加配置自动施法，仍无完整冷却/Runner。

## DEV-006 配置圆形技能（已实现）

SkillManager.TryCast 接收 SkillCastRequest（会话 ID、技能 ID），角色由管理器固定。校验会话状态、来源存活与技能存在，选择另一存活敌方小球；目标不由 Trait 查找。DEV-006 默认自身中心出生、朝敌方当前位置，DEV-007 将出生参考点、世界 XY 偏移、方向模式、固定角度及随机方向开关配置化，字段与默认值见 40。出生中心加偏移后按技能半径 Clamp 到场内；不会移动源球。生成后直线飞行，不追踪目标。

速度、半径、寿命和伤害从只读 CircleSkillDefinition 写入 CircleProjectileRequest，继续走 DEV-005 池、扫掠、过滤和统一承伤链。Trait 触发在结算边界之后，新弹道从下一子步开始移动，没有回填已过去的飞行时间。开战即发射在首个真实推进子步前执行。暂停/后台/死亡/结束/释放/旧会话请求均拒绝释放。

默认配置双方每 1000ms 发射，速度 12 格/秒、半径 0.15、寿命 2000ms、伤害 10；手动发射按钮在配置模式下调用该方第一个 Trait 引用技能，原型回归模式保留旧调试弹道。此单次生成无需空时间线 SO；尚未建设完整 SkillRunner 或编辑器。配置协议见 40，周期语义见 60，Unity 证据见 DEV-006。

## DEV-008 配置墙面反弹

DEV-008 增量（已实现，Unity 待用户验证）：CircleSkillDefinition/BattleContent 增加 bounceOnWall，SkillManager 将其传入 CircleProjectileRequest。CircleProjectileSystem 为实例保存可变速度，复用 LogicCore 的 SweepWalls/ReflectWalls，碰墙后继续查询同细段的剩余路径；配置关闭或省略时仍碰墙消耗。速度大小、寿命、AttackId 与统一承伤链不因反弹重置。墙与目标同刻时先处理墙，允许后续反弹段按原有初始重叠规则命中；无剩余时间时留待下一段，寿命到期则回收。每实例每查询细段最多反弹 64 次，后续撞墙超过预算则取消该弹道并增加 WallBounceBudgetExceededCount；WallBounceCount 记录实际反弹，角落算一次。此增量替代前文 DEV-005/007 关于不反弹、全生命期直线的历史限制；每次反弹之间仍为直线，不增加追踪。

## 首批时间线模块

优先落地二维范围命中、技能物生成、特效通知及必要生命周期模块。动作连招、预输入、蓄力 Gate、RootMotion、3D 位移，以及旧 ARPG 中依赖骨骼裁决命中或驱动位移的模块首版不迁入。

角色表现采用 Spine，按 [25_Render_Foundation.md](25_Render_Foundation.md) 在 View 层接入；技能侧提供释放与表现触发事实，不读取 Spine 骨骼姿态、动画事件或播放进度作为命中与伤害依据。

时间线帧是内容时间坐标，不是渲染帧。逻辑步跨过多个片段边界时，按顺序执行跨过的必要触发；暂停不推进，倍速统一改变战斗时间。

## 运动控制

吸血贴附由技能提交有时长和来源的运动控制请求，运动系统维护双方关系。Trait 不直接改 Transform，Buff 不自行约束两个球的位置。

实体小球、分身和物理召唤物使用 Dynamic；击退、拉近、冲刺、贴附与巡航恢复由运动系统统一仲裁，通过物理指令或约束执行，技能不直接争写 Rigidbody2D 或 Transform。不得每步强制恢复固定速度抹去物理冲量。具体状态优先级、指令 API 与调参在实现时确定，不作为现有接口。

物理回调只收集值数据，技能触发与承伤在会话物理子步结算边界编排；子步内已发生的物理响应不因死亡或贴附请求自动回滚。技能不得在回调里递归推进物理、直接扣血或立即回收其他实体。

## 生命周期与防循环

- 同一个能力可以持有持续技能物；一次瞬时释放不能无意重复生成整组环绕武器。
- 派生触发携带父来源、深度/次数预算和抑制标记；具体预算实现时确定。
- 普通周期技能与派生反击分开计时，不以一个全局阈值误伤正常释放。
- 派生请求排队处理，不在事件回调中递归完成整条施法链。
- 退出、重开、移除能力和实体死亡必须释放对应 Runner、技能物和运动控制关系。
- 首版结束战斗后停止新增命中；后续遗留地面物跨死亡存续等规则需单独设计。

## 编辑器

JSON 定义数值与规则，SO 定义时间线。二维锚点、XY 坐标、Z 轴旋转与运行时一致。旧 XZ、RotationY、CapsuleCollider、NavMesh 相关数据需要显式适配和校验，不能只替换 Vector3 为 Vector2。

### 时间与二维语义

- 60 FPS 画面目标、60Hz 默认逻辑步、物理子步和时间线内容帧各自表达不同含义。新资产建议使用显式 60 内容帧基准，并同时显示秒/毫秒。
- 若以后转换旧 30 帧资产，按实际时长换算，例如旧第 15 帧的 0.5 秒仍为 0.5 秒；不能只修改常量让所有技能时长减半。本次不自动导入旧 SO。
- 统一约定瞬时事件与持续窗口的边界，建议窗口使用左闭右开；跨步触发须按顺序补齐一次性事件，不用提高时间线帧率替代连续扫掠。边界语义在运行时与预览共用。
- 首版锚点候选包括自身、目标、墙接触点、技能物位置；方向独立指定发射方向、目标方向或接触法线。编辑器只开放已落地的语义，无对应触发载荷时不显示为可用能力。

### 首版编辑内容

建议界面保留技能/时间线选择、中央二维预览、底部轨道、右侧片段属性，并增加引用校验与命中诊断区域。JSON 信息只读并可定位文件；SO 片段可编辑。Trait/Buff 先维护 JSON，并提供引用关系展示，不在技能窗口内再建一套数值编辑器。

按运行时实际落地顺序开放：

1. 圆形范围命中与已实现圆形直线弹道的生成。
2. 技能物生成与回收，逐步增加静置蘑菇、环绕斧头及其命中显示。
3. 有来源和时限的运动控制请求，用于吸血贴附；具体约束由运动系统维护，面板不能直接编辑刚体位置。
4. 表现通知、特效和动画片段；Spine 资源未就绪时可用占位表现检查逻辑。

周期由 Trait/能力实例和战斗时钟维护，不需要把整场战斗展开成很长的重复时间线。基础接触攻击可继续走轻量命中入口。首版不迁入操作连招、蓄力 Gate、NavMesh 位移、3D 样条及无需求的霸体/无敌窗口。

### 两种预览及生命周期

- 内容预览：查看时间线、范围、锚点和表现采样；可拖动游标，但不把画出命中框视为战斗结算通过。
- 战斗预览：复用正式 BattleSession、运动、技能与承伤实现，先在 Play Mode 测试场景使用独立会话。配置来源可为编辑副本，但预览与运行时共用校验和执行模块，不另写伤害或贴附模拟。
- 动态战斗回看建议从相同初始条件重建并按固定步重放至目标时间；不能倒退 Transform 就认为 Buff、HP、命中记录已回退。编辑模式独立物理预览和加速缓存可后补，不承诺跨平台确定性。
- 预览不修改共享 JSON/SO；生成节点、物理场景、事件订阅、表现池和随机状态归预览会话。停止、关闭窗口、脚本重载、退出 Play Mode 必须清理；脏编辑副本提供保存/放弃流程。
- 诊断区建议显示当前战斗时间、触发来源、攻击/目标身份、实际 HP 损失、活跃技能物、查询预算和拒绝原因。日志有界，默认不逐步打印；性能最终在目标设备验收。

### 弹道与召唤物专项强化（新增需求与提案）

用户明确 ProjectBB 有大量弹道与召唤物，规模起点为同时约 300 个弹道 + 20 个有碰撞/血量的实体召唤物，整游戏目标 60 FPS。该规模是设计与验证输入，尚未达到或测试。强化召唤物编辑为已确定需求；下列 UI、模块与分批实现为提案，未实施。

对象先分为三类：普通查询弹道、静置/环绕技能物、具备质量/生命/技能的实体召唤物。实体召唤物引用角色定义并注册到 BattleSession；旧 SkillObject 的运动与调用壳不能直接视为完整实体。需要物理交互的投射物可单独采用 Dynamic，同一实例始终只有一个运动与命中权威。

界面增加可展开的“生成器/对象”工作区，与时间线互相定位：左侧是生成器及子技能引用树，中央是二维场地预览，右侧为对象的分组属性，下方同时查看技能时间线与选中对象的出生后时间。选择一个生成组即可编辑整组，无需为每颗弹道手工建轨道。

| 属性分组 | 建议强化内容 |
| --- | --- |
| 类型与来源 | 弹道/陷阱/环绕/实体分类，配置 ID、名称、外观、引用来源、主人/阵营；明确物理参与方式 |
| 生成与排列 | 每次实际生成数量、时间波次数/间隔、扇形/圆环/排布、角度/半径、随机散布与种子、锚点/偏移、出生越界策略；预览直接画生成点与方向 |
| 运动与轨迹 | 直线优先，随后环绕/追踪/规则反弹/二维曲线；速度、环绕半径/角速度等显示来源和单位，只开放已实现模式；路径控制点与范围可视化 |
| 命中与交互 | 受击/攻击/感知范围分层显示，目标过滤、穿透/消耗/重复命中间隔、墙响应；检测精度与伤害间隔分开 |
| 事件与子技能 | 生成、周期、命中、到达、到期等语义逐项实现后开放；引用子技能并显示对象局部时间。生成树检查循环、派生深度与数量预算，不依赖 NodeCanvas |
| 实体专属 | 角色定义引用、生命/质量/半径、初始 Trait/技能、受击与阻挡关系、简单跟随/追踪等行为引用；最终运动由统一控制入口提交 |
| 生命周期与容量 | 寿命、每来源/全场存量、满额行为、主人死亡/技能结束后的处理、回收原因；会话结束仍统一清理，任意子链都不能无限繁殖 |

旧字段 WaveCount 当前参与同时生成的空间排布，BulletPerWave 表示额外弹数；新 UI 应明确区分“空间方向组”与“有时间间隔的多波发射”，显示每次实际数量和预计总生成数，不仅改标签就假定具备分时发射功能。

JSON/SO 边界保持不变：配置数值只读展示并定位文件，时间线片段/空间内容按确定的唯一来源编辑；可为试验提供明显标记的临时预览覆盖值，但不隐式保存回 JSON。编辑源与最终生效参数分开显示，避免误认为只读字段已写入资产。

预览与诊断建议：

- 点选实例可追溯生成器、主人、子技能和回收原因；可单独显示一个生成组、显示轨迹残影、扫掠范围与命中点。仅隐藏表现不得改变战斗测试结果。
- 提供固定种子重放、移动目标、墙边折返、密集实体、持续生成和同刻爆发场景；实体/弹道上限由测试配置指定。
- 同时显示三类对象的活跃数/峰值、生成速率、池占用、拒绝数、候选查询与命中数、实际 PhysicsScene2D.Simulate 次数、物理/技能耗时与 GC。编辑器诊断不作为真机 60 FPS 证据，性能测试关闭重型 Gizmo 和逐条日志。
- 300 弹道 + 20 实体需在同一场景联合压测，区分稳定阶段和集中生成峰值；暂停、倍速、双方同死、主人死亡、循环重开继续回归。

实施顺序调整建议：先在批次 A 接通配置驱动弹道及首个实体召唤物的注册/清理；批次 B 就加入生成组面板、二维排列/轨迹预览和配置引用，不把召唤物 UI 全部推迟；批次 C 随实际机制扩展事件链与实体行为，并完成 300+20 联合压测。当前 128 弹道槽位、双球目标寻址和细分策略必须一起评估，不能只提高数组容量便声称支持该规模。

## DEV-009 召唤、四种能力与生成组（当前实现，待 Unity 验证）

- 配置 circleProjectile 的既有语义兼容；count/spreadDegrees 支持同时扇形/圆环生成。360° 不重复首尾方向；非随机基准方向仍按既有发射规则。一次生成可部分成功，失败计入相应容量/出生拒绝计数，不回收已成功实例。
- summon 引用召唤角色记录，创建有质量、血量与有限寿命的圆形实体。零偏移自身锚点自动向每条发射方向避开主人；显式偏移为世界 XY。越界或与任何实体重叠直接拒绝，不靠出生穿透制造攻击。首版召唤角色要求空 traitIds；不开放递归生成。
- area 以配置锚点瞬时查询，每攻击实例对每目标一次；不因靠墙而平移范围中心。样例一拳为自身中心、5 秒周期、半径 2、伤害 25。
- trap 由 onWall 事实的接触点生成，按半径向场内 Clamp；同球同子步墙角只触发一次，锚点取编号最小墙面的首个记录。静止技能物主动扫掠移动目标，首个合格敌方触发后消耗，免疫也消耗但不扣 HP。当前只有接触伤害，不含中毒。
- orbit 一次创建两把独立武器；各自记录目标与重复命中间隔。角运动按至多 2° 分段，以弦扫掠并加弓高保守余量，存在边缘近似，不宣称任意轮廓精确扫掠。lifetimeMs=0 仅对 orbit 表示持续至能力移除/来源死亡/战斗结束，其他类型仍必须有限寿命。
- drain 需要明确接触目标，双方仍存活且相距不超过半径和 + 0.15 格时建立 DistanceJoint2D 最大距离约束，保持当时距离、不瞬移拉回。双吸血鬼共用一个关系，各自周期独立，不刷新已有关系最大时长；到期边界不再跳伤害。外力请求、死亡、移除或退出解除。治疗按实际 HP 损失×万分比并受缺血量限制，不复活待死亡者。
- 技能物池 256、贴附关系 32；数量/寿命/命中记录有界。查询先记候选，边界再结算；命中去重不使用统一无敌时间。陷阱/环绕随能力移除回收；已发弹道和召唤实体沿各自生命期结束。

生成组编辑器入口：ProjectBB > 技能 > 生成组编辑器。JSON 提供数量/空间排列/技能数值，只读展示和定位；SO 编辑时间、主球 ID 和技能引用，最多 128 项，跨步按稳定时间顺序触发。多波通过多条时间记录表达；没有在 SO 重复保存 JSON 数值。普通序列化面板支持 Unity Undo/Redo，显式保存 SO。内容预览是初始布局示意，随机方向标注为示意；真实运行预览只在 Play Mode 启动独立会话，暂停/倍速/重建/关闭和退出清理。

本批为生成组编辑器最小版本，尚无完整可拖拽多模块轨道、对象事件/子技能引用树、回溯缓存、Spine 时间线或完整技能 Runner。
