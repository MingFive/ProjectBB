# ProjectBB 肉鸽选卡预留

## 当前状态

选卡属于第四阶段，目前仅确定“对战后构筑成长，再进入下一场”的扩展方向。候选数量、触发频率、刷新、稀有度、升级与失败处理尚未敲定，不能默认已经采用三选一。

## 职责分离

- 候选服务根据构筑状态和内容规则产生合法候选。
- 构筑管理层应用已确认选择，更新卡牌、Trait 与属性来源。
- UI 只展示候选和提交选择，不直接修改属性或实例化技能。
- 候选随机独立于战斗与表现随机，避免粒子或碰撞次数改变后续选卡结果。
- 在引入本地服务或真服务端时，裁决通过同一业务边界接入；不要求原型阶段先实现完整网络栈。

## 未来必须明确

候选批次身份、可选集合、重复选择幂等、失效批次拒绝、重开/退出时的生命周期，以及选择成功后属性和能力的应用顺序。

引入服务端后，候选和选择合法性由权威业务层管理，不把客户端快照自动当成真服可信状态。Protocol 只传纯数据，不放角色、Transform 或 Manager 引用。

## 不沿用的历史规则

旧 ARPG 的摇卡协议、元素锁定、传奇/双重卡、升级概率门控、特殊卡池和服务端状态结构均不自动迁入。确定本项目选卡玩法后再补配置与验收。
