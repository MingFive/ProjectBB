# ProjectBB 卡牌与 Trait

## 定位

Trait 表达小球初始能力与后续肉鸽构筑。Card 是玩家获得能力或属性的内容单位，不是另一套技能执行器。

首版即使用 Trait 表达四种球的触发能力，但选卡 UI 与完整肉鸽流程在基础能力验证后实现。

## 边界

- Trait 判断何时触发、是否满足条件，并提交技能/属性/状态请求。
- Skill 负责如何执行、寻找目标、范围、命中与技能物。
- Buff 负责临时状态。
- DamagePipeline 内的 Modifier 插入点负责本次命中修正，事后 Reactor 不重新执行整套公式。
- 普通属性卡通过统一属性修改器表达，不为每张卡建立 C# 类。

常驻能力与运行时实例分开；获得、升级、移除必须可追踪来源与撤销，不修改共享配置。

## 首版触发语义

计划支持战斗开始、新球体接触、撞墙、战斗时间周期、有效造成伤害、有效承伤和死亡/击杀相关事实。具体事件名、参数及可用时机以代码为准。

“空间接触”与“有效造成伤害”不是同一个触发：免疫伤害不阻止反弹，是否触发碰撞能力取决于它监听哪种事实。

同一次球体碰撞的事后触发在双方承伤和死亡提交规则之后排队执行，不插入双向结算中途。

## 四种球的组合

| 能力 | Trait 的作用 | 执行归属 |
| --- | --- | --- |
| 吸血鬼 | 新接触时申请能力 | 技能协调周期命中，运动系统维持贴附，Buff 提供减速 |
| 一拳超人 | 周期请求爆发技能 | Skill 执行以自己为中心的范围攻击 |
| 提莫 | 墙体撞击时提交锚点 | Skill 生成蘑菇，技能物触发独立命中技能 |
| 狂战士 | 开战建立持续环绕能力 | Skill 管理两个斧头实例和命中 |

周期属于战斗时间，暂停不累计。首次触发在开战立即发生还是等待首个周期，由具体能力配置明确。

## 触发安全

冷却、触发间隔、次数预算和派生链抑制是不同维度。重复撞墙、伤害反击和技能派生不能依靠一个全局冷却粗暴合并。

Trait 只在实际提供的事件上配置，不假定旧 SkillStart/SkillEnd 等事件已经派发。无法解析的触发时机在配置校验时失败。

命中与技能参数修改由消费方解释，Trait 不登记所有技能内部专用参数，不恢复已废弃的专用参数拉取模型。

## DEV-006 周期 Trait（已实现）

角色持有 TraitManager，会话绑定已解析的 PeriodicTraitDefinition。只处理 periodic；不把尚未实现的撞墙/受伤等触发显示为可用配置。计时状态、移除标记及计数均属于角色实例，共享定义不可变。

第一次触发由 fireOnStart 决定；普通周期在 t=period 开始。以绝对周期序号乘周期计算到期时间，在下一个物理结算边界触发，量化延迟小于一个 1/120 秒子步，不逐轮累积漂移。按 FirstBall、SecondBall 和各自 traitIds 顺序提交请求；Trait 只提交会话与技能 ID，SkillManager 负责索敌、方向与生成。

暂停/后台不推进，倍速只改变会话固定步数量。致死和超时边界先终止战斗，不再触发到期 Trait；Dispose 停止所有实例。请求因满池等原因失败仍消耗该周期并计数，不在下一帧补发。Remove(id) 幂等停止未来触发，已发出的弹道独立完成生命周期；结束/重开统一清弹道。当前没有升级、属性修改器、事件反击和通用派生链。

## 后续肉鸽（待实施）

整次肉鸽尝试持有卡牌和构筑，进入单场时投影到小球。临时接触、当前 Runner、技能物和接触命中记录不跨场继承。

跨场 HP、Buff、冷却、卡牌升级/替换、敌方构筑及候选权重尚未确定。不能自动引入 ARPG 的元素槽、传奇/双重卡门控和卡牌 ID 号段。

选卡与候选流程见 [61_Card_Draw_System.md](61_Card_Draw_System.md)。

## DEV-009 事件能力（已实现待 Unity 验证）

周期实例类型暂保留 PeriodicTraitDefinition 名称，但已明确携带 Trigger。支持 periodic、onStart、onWall、onContact：开战触发只在首次实际推进执行一次；墙与接触事实在本边界既定伤害后交给存活来源，事件触发保护使用各 Trait 独立 periodMs，不做无界补发。

Trait 只提交技能 ID、明确目标或墙锚点，索敌与生成由 SkillManager 执行。Remove 幂等停止未来触发，移除对应持续技能物/贴附；已发普通弹道与实体召唤沿原寿命，主人死亡/战斗结束统一清理。升级、永久属性修改器、卡牌候选与通用伤害派生仍待实施。
