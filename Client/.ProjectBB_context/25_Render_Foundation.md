# ProjectBB 二维表现与渲染

## 首版表现基线

- 横屏，固定正交战斗相机，完整显示竞技场。
- 逻辑使用 XY 平面；Z 用于表现层级或相机方向，不引入 3D 战斗高度。
- 不使用 ARPG 的透视顶视、竖屏 FitWidth、NavMesh 和角色跟随作为默认方案。
- 优先使用简单 Sprite、共享材质、图集与 Unlit 风格。
- 2026-10-10 空工程文件核对：当前采用 Built-in 渲染管线、Linear 色彩空间，SampleScene 含正交相机。正式质量档与平台 SDK 待平台验证；这些初始设置不代表平台兼容性已通过。

## 相机与适配

DEV-006：ProjectBootstrap 启用时设置 Application.targetFrameRate=60、QualitySettings.vSyncCount=0，让桌面不以 vSync 覆盖目标帧率。Unity 集成测试已断言此设置；60Hz 逻辑时钟独立保持。编辑器统计不是小游戏/真机稳定 60 FPS 的验收证据，300 弹道 + 20 实体仍待后续联合压测。

按实际可用战斗视口同时适配场地宽高，加上球体外观和特效所需边距。窄宽比、超宽屏和安全区通过留白与 UI 布局适配，不拉伸或改变逻辑场地。

同一场战斗只有一个权威相机装配入口。震屏只改变表现，不修改场地、球位置或命中结果。

## 动作与动画方案

状态：2026-10-10 用户已确定首版采用“分层图片 + Spine 角色动画，少量序列帧辅助特效”，替代此前“分层图片 + 序列帧、骨骼非首版依赖”的约定。当前为设计已确定，资源制作与运行时接入待实施。

### 资源与制作分工

- 小球按球体底图、五官、装饰、武器和特效拆分，按角色实际需要提供，不强制每个角色都有全部层。
- 角色主体由 Spine 制作与播放待机、移动姿态、碰撞、受击、施法和死亡动画，通过分层图片的骨骼变换及必要的网格变形完成；场内真实移动仍由战斗逻辑驱动。
- 序列帧仅作为辅助，按需用于冲击、爆炸、烟雾、毒液等复杂特效，不为角色常规动作制作整身逐帧图片。闪白、拖尾、光圈可由材质、粒子或简单图片动画完成。
- 优先为结构兼容的小球复用骨骼和通用动画，通过附件与 Skin 替换五官、装饰和皮肤；不强制结构差异大的角色共用同一骨架。
- 拆图需约定统一的球心、尺寸基准、枢轴、挂点和前后遮挡关系；同一序列的各帧保持对齐，避免切帧时跳动。
- 角色差异优先通过底图、五官、装饰和少量专属反馈表达；共用反馈参数与角色专属资源分开，具体配置结构在实现时确定。

### 制作与接入计划

- Spine 是首版角色动画方案；Unity 侧计划通过 spine-unity 在 View 层接入，GamePlay 与 LogicCore 不依赖 Spine 类型或动画资源。
- 制作前核对实际 Spine 编辑器、导出数据与运行时版本的兼容关系，记录所选版本；本次决策不代表已经安装运行时或完成平台验证。
- 保留可编辑的分层原图与 Spine 工程，运行时使用导出的骨骼/动画数据、图集及纹理，不将角色动作重新烘焙成整身序列帧作为默认交付。
- 先制作一个代表性小球，验证通用动作及兼容结构的换皮，再推广到四种能力。动画名称、附件命名、混合与打断规则随样例确定，不在缺少资源时假定现有接口。
- 目标是减少逐帧绘制与重复纹理；新增拆图、绑定和动画制作工作，实际包体、内存和运行成本以样例及目标设备测量为准。

### 首批表现制作参考

以下是制作与调试起点，具体画法、幅度、时长、帧数和播放速率待实际画面验证，不是已完成资源或最终参数。

| 场景 | 表现方向 |
| --- | --- |
| 待机与移动 | Spine 表现轻微呼吸、眨眼、倾斜或拉伸；按需要增加拖尾 |
| 撞墙与撞球 | Spine 表现沿接触法线短促压扁并回弹，不改变逻辑反弹过程 |
| 受击 | 短促闪白、表情变化，与碰撞挤压组合 |
| 施法与死亡 | Spine 表现施法蓄势、脉冲与死亡动作，按需搭配淡出或破碎特效 |
| 吸血鬼 | 咬合表情、贴附期间轻微脉冲，血滴或连线表现吸血 |
| 一拳超人 | Spine 驱动拳头部件伸出与回收，配合冲击波特效；拳头动画不裁决命中 |
| 提莫 | 身体轻弹、蘑菇出现反馈，毒雾或爆开序列帧 |
| 狂战士 | 两把独立斧头图片环绕，配合刀光；显示与检测使用同源角度 |

有五官的小球优先保持脸部大致直立，滚动感可由身体纹理或装饰表达；最终朝向风格以战斗尺寸下的辨识度为准。

### 表现驱动与逻辑边界

- 动画属于 View。位置投影与外观形变分层处理，挤压、抖动只作用于外观子节点，不修改逻辑位置、半径和速度。
- 2026-10-13 双球 Dynamic 已迁移：实体表现消费 GamePlay 物理适配提供的模拟快照，物理节点与 Spine/外观节点隔离；只选择一套位置插值来源，不让刚体插值与 View 插值重复平滑。死亡在物理子步结算边界停止后续推进，不用拉回显示位置冒充物理回滚。
- 武器轨道、血条等与身体形变隔离，不能因身体缩放或五官朝向调整而改变逻辑武器轨迹或拉伸血条。
- 同一外观属性由统一的表现入口组合或仲裁；Spine 与程序反馈不能同时争写同一骨骼或变换。连续受击的重触发、动画混合与死亡打断规则在实现时明确。
- Spine 播放只保留一条时间推进入口，不能由运行时自动更新与会话接入重复推进。序列帧按经过的战斗时间采样，不能每个渲染帧固定前进一张图；两者及战斗特效统一响应会话暂停和倍速，UI 动画仍使用独立时钟。
- 技能释放、命中、受伤与死亡事实驱动表现；动画事件、当前图片或播放完成回调不裁决命中、扣血和胜负，也不默认阻断小球运动。
- 对象池复用时重置 Spine 动画轨道、混合状态、姿态、Skin、附件、局部变换、颜色及辅助序列帧进度，清理事件订阅和绑定关系；旧动画回调不得作用于新实体或新会话。

先用一个代表性小球验证移动、碰撞、受击、施法和死亡，再验证四种能力；资源量和性能预算以目标平台测量为准。

## 角色与命中反馈

- 表现根和逻辑状态分离，小球位置来自会话状态，支持渲染插值。
- A 方红色、B 方蓝色；血条消费角色资源变化。
- 伤害飘字为小球左上方白色小字渐隐，展示实际 HP 扣除量。
- 护盾吸收、治疗的颜色和文字规则待内容设计，不冒充 HP 伤害。
- 闪白、缩放、拖尾只改变外观，不改变逻辑半径、速度或阵营。
- 狂战士斧头显示角度与逻辑角度同源；特效不可成为旋转伤害检测的事实源。

## 生命周期与性能

- 2026-10-13 用户确定整个游戏以 60 FPS 为目标，单帧预算约 16.67ms；覆盖战斗、UI 与表现，目标设备和压力场景规模待明确。当前未接入统一目标帧率设置，也未完成真机性能验收。
- 渲染帧率目标与战斗时钟分开：当前默认 60Hz 逻辑步、每步两个物理子步，高速弹道可进一步细分模拟；不能为满足 60 FPS 而直接取消必要扫掠或子步。物理、技能物、Spine 和特效共同纳入帧预算，具体容量以目标平台实测确定。
- 小球表现、蘑菇、斧头、特效、飘字分别有明确的会话与实体归属。
- 对象池复用时清理上次文本、颜色、时间、绑定目标和命中表现状态。
- 蘑菇数量、特效数量、飘字数量和寿命有上限；具体预算根据真机 profiling 确定。
- 无主对象不得无限存活；战斗结束与重开应清理所有本场表现。
- Gameplay 暂停与 UI 动画时钟分开；暂停菜单可继续交互。
- 不沿用 ARPG 的三角面预算证明 2D 项目性能，重点测 Spine 动画更新、骨骼与网格变形、透明叠加、粒子、DrawCall、内存、GC、包体和加载。

## 验证范围

先验证固定竞技场与四种球的完整可见性、插值与命中反馈，再确定正式渲染设置。当前已有模板相机及默认图形、质量配置。

DEV-002 已增加 BattlePrototypeView：运行时生成共享圆形 Sprite、红蓝球、矩形场地与有数量上限的网格；位置读取逻辑前后状态插值，相机按场地宽高与当前视口同时适配。临时 IMGUI 控件提供暂停、继续、1×/2×及同种子重开，属于运动验证工具。

DEV-003 增加读取 CombatManager 的血条与生命数字、实际 HP 损失飘字、0.12 秒闪白、死亡变暗及胜负/超时显示。最多保留 32 个飘字，寿命 0.8 秒；不缩放逻辑球体。暂停、后台暂停与倍速服从会话时间，结束后仅表现时间继续淡出，不再推进运动或伤害。结算后禁用暂停/倍速操作，重开仍可用。参数为原型起点，尚未经过视觉验收。

表现由 SceneInit 调用，不自行 Tick；释放时清空反馈，停用并销毁表现根、生成的 Sprite 和圆形 Texture，恢复原相机设置，不释放 Unity 持有的白纹理。正式角色资源、Spine、UI 安全区适配仍待实施；DEV-004 已执行真实 Bootstrap Play Mode 集成与 16:9 画面检查；多视口、完整飘字/闪白视觉及平台表现仍待专项验收。
