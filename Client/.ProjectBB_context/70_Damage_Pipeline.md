# ProjectBB 命中与伤害结算

## 三类事实

1. 接触：球墙/球球的空间关系，决定运动响应与接触触发。
2. 技能命中：攻击在空间或指定规则上接触目标。
3. 有效承伤：命中经过状态、免疫、护盾等处理后得到实际结果。

伤害无效不能反向抹去物理接触。DamagePipeline 不进行几何检测，碰撞系统不直接扣血。

## 分层与链路

碰撞或技能检测 → SkillManager 命中入口 → GamePlay DamagePipeline → LogicCore 公式 → CombatManager 承伤 → 结果与事后事件。

LogicCore 接收纯属性快照与输入，不接收 BallCharacter、SkillManager、BuffManager、Unity 对象或配置 SO。完整编排仍属于 GamePlay。

基础碰撞攻击可跳过完整时间线，但不跳过统一命中与承伤入口。持续伤害可使用专用公式路径，仍必须收口到同一承伤与死亡机制。

## 首版数值范围

先实现生命、有效移速、碰撞攻击与四种能力所需伤害。无修正时一次基础碰撞每方受到 10 点伤害。

暴击、护盾、伤害类型等仅在内容需要时启用；背击、方向闪避、旧连击和复杂元素乘区不作为首场战斗前置条件。

迁入公式前检查现有属性枚举、取整、来源和结果字段，不能凭文档假定签名一致。

## 双向碰撞批次

同一次新球体接触形成一个批次，捕获批次开始时双方是否有效以及必要攻击/防御状态：

1. 生成 A→B 与 B→A 两个独立请求，保留各自攻击来源与碰撞实例身份。
2. 按批次开始时的有效性完成双方基础命中与承伤；不能因首先处理的一方进入待死亡就取消另一方向的既定请求。
3. 本批次内禁止事后 Reactor 插入新的伤害、清空对方技能或提前回收实体。
4. 两个方向处理完成后，根据承伤结果判定待死亡集合；本批次已致死者不能靠随后吸血自动复活。
5. 对仍存活且满足条件的来源处理本批次治疗，随后提交死亡与一次性清理。
6. 发布批次事后结果，队列中的派生技能重新校验来源和目标；双方均死则平局，否则确认胜负或继续。

基础互伤的同时性只作用于这个明确批次。其他不同时间命中仍按时间处理，不能把整个渲染帧的所有技能强行合并为同时命中。

同一时间的不同攻击采用稳定顺序；排序不能依赖 Dictionary 枚举、对象地址或 Unity InstanceID。

## Dynamic 迁移后的结算边界

2026-10-13 双球 Dynamic 结算适配已实现并通过 Unity 集成验证。由 BattleSession 统一驱动物理子步；回调只复制必要接触值数据，子步结束后归并为实体接触及技能命中事实，按明确的稳定规则逐批结算。多子 Collider、多接触点和双方回调不能各生成一次互伤。

Dynamic 接触没有供业务直接重建完整步内顺序的精确 TOI，时间按所属子步边界表达；Cast 路径比例不自动等价于所有动态事件的真实发生时刻。同边界不同来源的排序规则须在实现时显式记录并验证，不把回调先后当成物理时间；同一互伤批次锁定双方请求，其他后续批次仍重新校验有效性，不将整步伤害合并成同时批次。

死亡提交后不再推进下一子步或接受后续无效请求；本子步已经发生的运动与响应不自动回滚。不再要求动态实体复用旧实现“精确停在首次致死接触点”的行为，子步精度与可接受位移误差通过专项验收确定。截止结算边界先处理合法接触，再处理未结束战斗的超时；末步对齐策略随迁移明确。

## 承伤与死亡

- CombatManager 处理状态拦截、扣盾/扣血及必要资源变化。
- BattleSettlementSystem 负责批次和死亡提交顺序，不绕过 CombatManager 改生命。
- 待死亡、正式死亡、回收要区分；待死亡实体只允许完成已捕获批次的必要工作，不再接受任意新释放。
- 死亡事件每个实体只发布一次，胜负每场只确认一次。
- 批次中不立即清 Buff、取消技能、释放贴附或回收实体；这些操作在提交阶段统一完成。
- 迁入旧 OnDeath 即时清理行为时必须调整，不能只增加一个队列就宣称双向结算公平。
- 首版技能请求在战斗结束后不继续造成伤害；延迟回调必须核对会话状态。

## 结果语义

设计结果需要区分请求是否被接受、实际 HP 损失、实际护盾损失、实际治疗及是否致死。当前 DamageResult 已区分 Accepted、WasImmune、HpLoss、WasLethal，并保留请求与目标接触位置；CollisionBatchResult 提供双方结果与发生时间。护盾和治疗字段随对应能力实现，不以一个 bool 同时代表几何碰撞与伤害成功。

旧文档中 ActualDamage 包含 HP 与护盾消耗，不能直接作为本项目的吸血数值。

吸血建议值为本次实际 HP 损失乘吸血比例，治疗不超过缺失生命；免疫、完全护盾吸收、过量伤害和自身已致死时不得错误回满或复活。

伤害飘字显示实际 HP 扣除量。护盾和治疗反馈作为独立表现，不把请求伤害值当作最终伤害。

## 去重与来源

基础碰撞使用接触轮次；范围攻击使用攻击实例；蘑菇和斧头使用各自技能物/攻击周期；吸血使用接触关系与周期身份。不得以一个全局受击冷却吞掉不同来源的合法命中。

Skill、Buff、Trait 派生请求保留原始来源与父链，死亡后统计与归属仍能查询纯结果，不强依赖已销毁表现对象。

## 关键验收

双方各剩 5 HP、基础伤害各 10 时应平局；改变注册/遍历顺序结果不变。另测免疫单方、过量伤害、护盾吸血、双向不同伤害、派生反击、单次死亡、暂停与重开后旧请求失效。

## 超时规则

2026-10-12 用户确定按剩余生命比例判胜负。当前原型时限默认 180 秒，可在 Bootstrap 修改；比例相同平局。结算采用当前 HP 与对方最大 HP 的 long 交叉乘积比较，避免大数与浮点误差。截止时刻先完成碰撞批次；若已因死亡结束，不再覆盖为超时结果。

## DEV-005 弹道命中结算（当前增量）

2026-10-13 已接入圆形弹道：查询池按实体过滤和路径距离选中首个目标，每个弹道生命期最多提交一次；结算器再次核对会话、来源、目标、阵营与死亡状态。命中经 SkillManager 捕获 Projectile 来源请求，沿现有 DamagePipeline / CombatManager 扣血，再单独提交本次死亡与胜负。AttackId 与接触 ContactRound 分开，免疫是 Accepted=true、WasImmune=true、HpLoss=0，并消耗弹道。

同一名义物理子步边界先结算球球双向批次，再按 AttackId 递增处理弹道单向批次，最后超时。弹道候选的路径时间只用于该弹道选择首个目标，不与 Collision2D 回调伪造的 TOI 混排。先致死的弹道使后续来源失效；不同弹道不承诺同时互杀。5/10 球球互伤仍同死平局，包括同边界还有弹道候选的情况。

弹道反馈单独保存至最多 64 项的值快照队列，丢旧反馈只影响表现；实际 HP 损失、命中次数和回收不丢失。结束/超时清在途实例，释放清队列；当前没有通用派生队列或完整技能取消系统。Unity 集成验证通过，证据见 outputs/projectile_validation。

## DEV-006 自动技能与结算边界

DEV-006 增量：配置圆形技能继续生成原 CircleProjectileRequest，经 SkillManager → DamagePipeline → CombatManager 承伤，不新增 Trait 直接扣血路径。物理子步边界仍先球球互伤、再按 AttackId 结算在途弹道；结束/时限检查通过后才允许周期 Trait 请求下一批弹道。因此恰逢致死/超时边界的周期不新增攻击，普通弹道仍不具备双向同时互杀语义。

## DEV-003 实现范围（历史）

本节是旧自管双球源码的历史实施证据；Dynamic 适配见 DEV-004，历史通过结果与迁移后证据分别保留。

- LogicCore 的 DamageFormula 只计算免疫与实际 HP 损失；GamePlay 的 SkillManager 捕获基础碰撞请求并转入 DamagePipeline，CombatManager 唯一负责扣血与死亡状态。
- BattleSettlementSystem 按会话身份与递增接触轮次去重；拒绝同阵营、无效时间、已关闭/已结束及批次开始时已死亡或待死亡的实体。双方请求在扣血前捕获，先承伤者不能因此失去本次既定攻击。
- 当前无治疗和 Reactor，双方承伤后统一提交死亡，再确认一次性结果；不在批次中调用表现或外部同步事件。死亡只有状态提交与计数，通用死亡事件、技能取消及派生攻击队列尚未接入。
- 会话公开有界值快照供 View 消费；无人消费时保留最近 64 批并累计丢弃反馈数，不改变承伤事实。释放关闭结算器并清空反馈；结束后不接受新碰撞伤害。
- 当前仅基础生命、碰撞伤害与只读免疫开关。护盾、吸血、Buff、Trait、完整技能时间线与四种能力均未实现。
- 18 项新增战斗用例及原有 19 项运动用例在纯 C# 环境通过。覆盖 5 HP 双方致死、异伤害交换注册顺序、免疫、过量伤害、重复/过期请求、墙面、持续接触/重撞、结束截步、超时比例/相等/大数/边界、暂停/后台、重开及反馈预算。Unity 编译、Test Runner 和场景视觉尚未验证。

## DEV-004 双球物理结算验证

双球接触由 BallContactRelay 收集，BallCollisionSystem 在 Simulate 返回后按稳定双球身份归并；BattleSession 同步模拟快照后调用原 TryResolveContact。墙面计数先更新，球球新轮次形成独立双向批次；目前没有其他攻击来源参与同边界排序。两个请求先捕获、双方承伤后提交死亡的原流水线保留。

默认子步 1/120 秒，接触时间采用完成的子步边界。5 HP／10 伤害正碰在第一个子步双方同死平局，停止本帧后续子步，结果仅提交一次。时限不足一个子步时截短；该边界合法接触先于超时判定。持续接触、真实重撞、免疫、初始穿透及 Bootstrap 重开均通过实际 Play Mode 集成。来源扩展、治疗和派生技能尚未实现，不能据此认定其已通过。

## DEV-009 多实体与能力结算（已实现待 Unity 验证）

用户确定只以两个主球裁决胜负；召唤物死亡仅回收自身，主人死亡时其召唤物清理，场终清全部临时对象。超时继续仅比较两个主球生命比例。召唤物击杀主球时胜者仍为胜方主球身份，不返回召唤物 ID。

边界顺序：按实体 ID 有序接触对逐对完成双向批次 → 普通弹道按 AttackId → 陷阱/环绕按生成身份、目标按实体 ID → 有界贴附周期 → 存活者事件 Trait → 安全清理 → 周期 Trait/生成时间线；截止边界不触发新 Trait。后续批次重新验证来源/目标，单个接触批次依旧捕获双方请求后才死亡提交。范围技能在安全触发入口逐目标处理，任一主球死亡结束后不追加伤害，不把整个范围/子步并成同时互伤。

新增 DamageSourceKind.Skill=2，保持 Collision=0、Projectile=1。能力命中继续经 SkillManager.ResolveCapturedHit、DamagePipeline、CombatManager；AbilitySystem 不直接改 HP。吸血为每方向独立周期单向请求，按实际 HP 损失治疗存活来源并提交目标死亡；不具有不同弹道/不同周期同时互杀语义。

反馈复用有界值快照入口，召唤血条与技能物只读展示。暂未增加治疗飘字、护盾及完整派生事件链。
