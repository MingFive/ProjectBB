# ProjectBB 小球运动与碰撞

## 设计状态与范围

2026-10-12 用户明确：后续技能会改变物理运动，实体小球、分身和具备物理属性的召唤物采用 Unity Physics2D Dynamic。其他已讨论方向按本文执行。DEV-004 已完成两个圆球与矩形墙的 Dynamic 迁移；DEV-005 已接圆形高速弹道并通过 Unity 集成验证，扩展实体待实施。DEV-002/003 自管运动已退出运行路径，源码与旧 Unity 基线保存在 outputs/dynamic_validation/baseline，历史证据不替代新物理验收。

第一批实现范围为矩形竞技场、两个圆形 Dynamic 实体与圆形高速弹道。后续再验证一个具备质量的圆形分身/召唤物，扩展精细形状、四种能力和性能容量；不一次建设完整通用物理框架。

## 对象与职责

| 对象 | 目标实现 | 职责 |
| --- | --- | --- |
| 小球、实体分身、物理召唤物 | Dynamic Rigidbody2D + Collider2D | Unity 求解碰撞、分离及物理响应，GamePlay 提交运动控制与消费模拟事实 |
| 普通大量弹道 | 逻辑轨迹 + 主动形状扫掠 | 命中、穿透、规则反弹、消耗；不默认加入动态接触求解 |
| 需要物理交互的投射物 | Dynamic，按需 Continuous | 参与实际动量交换、弹跳和推挤 |
| 墙体 | 静态碰撞体 | 阻挡与接触法线，默认不造成伤害 |
| 陷阱、索敌与范围攻击 | Trigger 或主动查询 | 空间事实与触发，不直接扣血 |

实体阻挡、受击范围、攻击范围和感知范围分别表达，可以复用形状但不混淆响应。组合形状的子 Collider 映射到同一稳定实体身份；普通弹道之间默认不做无意义的实体碰撞，阵营、主人与目标资格由业务过滤补充。

物理适配归 GamePlay，SceneInit 负责装配；LogicCore 只保留纯几何、公式和纯数据。动态刚体的模拟结果是实体位置与速度的权威；BallMotor 转为运动状态与指令入口，不再同时积分或重复反弹。View 节点从模拟快照投影，与物理节点分离。

## 坐标与速度

- XY 战斗平面，Z 轴旋转；格子与世界单位的转换集中配置。
- 圆形实体出生位置校验采用场地边界向内缩进逻辑半径；复杂形状按实际形状检查合法出生与初始重叠。
- 标准移速档位 100 对应统一格/秒巡航基准；Buff 与 Trait 修改有效目标，不直接改写标准值。
- Dynamic 的质量、摩擦、弹性、阻尼与旋转约束作为物理参数；零重力影响、低摩擦等是原型调参起点，不承诺弹性为一即可保持每个球自己的速度大小。
- 主球采用目标巡航速度与受限恢复过程，击退、冲刺、停止、贴附等由明确的运动状态仲裁；不得每步无条件归一化速度抹去冲量。恢复速率、冲量衰减和状态优先级在最小闭环中调试记录。
- 碰撞分离与正常物理响应交给 Unity，不能再执行原球球反射算法；需要特殊响应的技能通过统一运动入口提交力、冲量、目标速度或约束请求，具体 API 待实现。
- 零速、近零法线与数值退化必须有稳定处理，不能把零向量归一化。停止效果解除后保留可恢复的运动方向。
- 接触容差与恢复策略不得导致抖动、持续零时刻反弹或异常增速；多个接触同时作用时验证稳定性。

## 固定时钟

初始逻辑步长仍以 1/60 秒为验证起点。BattleSession 在脚本模拟模式下统一推进 Physics2D，或推进其明确持有的 PhysicsScene2D；物理世界的所有权与全局设置恢复必须明确，不能误驱动其他场景的对象。禁止自动物理步与会话重复推进，禁止在回调中递归 Simulate。运动、技能、Buff、持续伤害和胜负计时使用同一战斗时钟。

为减少接触到结算的延迟，可将逻辑步拆成固定物理子步，每个子步结束即收集并处理该边界上的事实；子步数量与性能预算待测，不能将倍速改成一次更大的物理步。补步/子步预算耗尽要记录诊断并限制积压，不用未经验证的大步补算。

渲染帧可包含零个或多个逻辑步；表现只选择一套插值来源，不与刚体插值重复平滑。暂停、结束和重开要同步插值状态。当前代码的“单步最多 64 次碰撞”是旧自管算法预算，不能当作 Unity 求解器参数。

前后台恢复不能把离开时长一次性补成大量伤害。首版按暂停恢复处理；离线战斗另行设计。

## 检测与响应

Dynamic 实体按需启用 Continuous；它解决部分高速实体碰撞问题，不替代技能扫掠、Trigger 穿越和旋转路径的专项验证。不能仅在位移终点做重叠测试。

普通弹道使用 CircleCast 等查询作为形状检测手段，返回必要的目标、距离、法线和接触位置。查询不自动包含目标在整步中的运动；圆形弹道与圆形移动目标可复用相对运动计算，但不能把经历过反弹的整步轨迹假定为单一直线。实施时明确物理子步、目标运动近似、误差容限与跨越检测，双向高速交叉必须单独验收，不能承诺任意动态轨迹的精确连续检测。

查询型弹道命中目标后可通过运动入口请求击退，不必为此改为 Dynamic；实体物理和查询不得对同一投射物重复生成命中。查询结果缓冲复用，容量满时显式处理并诊断，不能静默遗漏有效目标。

## 物理步与结算边界

每个物理子步的编排为：提交本步运动控制 → 模拟并收集接触值数据 → 完成本步技能查询 → 归并接触与命中 → 按明确稳定规则逐批结算/提交死亡 → 应用安全的生命周期变更与发布表现结果。具体接口与不同来源的同边界优先级在实现时列明并验证，不能依赖回调/字典遍历顺序。

普通 Collision2D 回调没有可直接重建精确步内碰撞时间线的时间字段。动态接触以物理子步边界记录，不伪造精确 TOI；查询得到的路径比例也不能直接冒充与所有动态接触可比较的真实时间。每次实体互伤仍为独立双向批次，不把整个子步、逻辑步或渲染帧的全部伤害合并为同时伤害。后续批次重新校验来源与目标有效性。

战斗在结算边界结束后不再推进下一子步，不承诺在 Unity 内部首次撞击时刻中断。增大子步精度只能缩小误差，不能撤销本子步已经发生的运动响应；不采用只回拉显示位置来冒充逻辑回滚。截止边界先处理属于该边界的合法接触，再按剩余生命比例判断超时；时限与子步的对齐/末步策略在实现时明确验收。

## 接触生命周期

每对球使用无序实体对标识并记录接触轮次，分为开始、持续、结束：

- 开始：产生一次基础双向碰撞攻击，并提供接触触发事实。
- 持续：不追加基础碰撞伤害；独立周期技能可以继续结算。
- 结束：超过分离容差后解除接触，后续重新相撞才开启新轮次。

伤害方向 A→B 与 B→A 是有向请求，不能因接触对无序而合并为单次伤害。

墙体接触提供边界身份、位置、法线和所属物理子步。角落同一撞击可能涉及多个边界；提莫首版按同一撞击归并为一次触发，不能因为两条边重复生成蘑菇。

双方回调、多个接触点和多个子 Collider 统一归并；单个子 Collider 退出不能提前结束整个实体接触。初始重叠、池化启停、约束切换及接触抖动不得伪造攻击。池化重新启用时重建本次身份、过滤/忽略关系，清空旧接触与命中记录。

接触事件语义与事件名称分开：上述是待实现语义，不是已经存在的 EventCenter 常量。

## 吸血贴附

单纯减速不能保证反弹后仍有接触，因此使用显式、有最大时长的贴附关系：

1. 新接触建立碰撞批次，先完成基础互伤与死亡判断。
2. 双方仍有效且能力允许时，在结算边界提交贴附请求，在下一物理子步前建立受控关系；不沿用旧方案“在 Unity 内部反弹前同步插入贴附”的假设，也不将已经弹开的球直接瞬移拉回。
3. 贴附关系由运动系统经物理约束或受控运动维护，双方临时速度修改由带来源的 Buff 表达；具体约束方式在能力实现时验证，不与动态刚体争写位置或制造穿透。
4. 有效贴附期间按独立周期产生吸血命中。
5. 到期、死亡、强制位移、能力移除或战斗退出解除关系，移除本关系来源效果，存活单位恢复正常反弹与移动。

关系本身不会因连续 Stay 无限刷新。双方都是吸血鬼时，同一接触对只维护一个运动关系，各自伤害周期独立，并受关系最大时长约束。

不在接触事件里互相递归设置位置；不移除其他来源的减速。解除关系后的分离过程不会重复结算同一接触基础伤害。

贴附时长、减速幅度、吸血周期尚待配置。规则实现必须与 [70_Damage_Pipeline.md](70_Damage_Pipeline.md) 的致死与治疗顺序一致。

## 形状扩展与性能

首批圆形闭环后按内容增加胶囊、旋转矩形、低复杂度多边形与组合形状；身体、受击和攻击轮廓按实际用途制作。支持精细轮廓不等于无限增加顶点，Spine 外观形变不能直接驱动权威碰撞形状。旋转/曲线运动需专门扫掠或按误差细分，普通平移 Cast 不覆盖旋转扫过区域。

性能关注活跃实体、实际接触数、形状复杂度、Continuous 数量、查询次数、物理同步与生成峰值。先采用碰撞层过滤、复用查询缓冲和池化；不预先承诺数量上限或一律上空间网格。压力档可用弹道 100/300/1000、实体召唤物 10/30/100，分别测分散运动、密集接触和集中生成；这些是测试输入，不是已测容量。平台确定后记录目标设备的 Physics 2D Profiler、GC 和帧耗时。

2026-10-13 用户明确首个联合规模起点为同时约 300 弹道 + 20 个有碰撞/血量的实体召唤物，60 FPS 为游戏目标，设备与平台待明确。20 个召唤物之外仍有基础对战小球。先验证多实体身份、注册/移除、归属/阵营、目标查询、接触归并和池化重置，再做联合压力测试。当前双球寻址和 128 弹道池未满足此需求；现有依目标速度细分整个物理场景的策略扩展到多实体时需测最坏速度、实际 Simulate 次数与预算耗尽行为，不能以单纯增加容量替代验证。候选裁剪、空间索引与批量更新按测量引入，不预设 ECS 或第三方弹幕插件为必要依赖。

## DEV-005 弹道查询与物理细分（当前增量）

- 普通圆形弹道不创建 Rigidbody2D/Collider，不参与推挤。LogicCore.ProjectileGeometry.Sweep 计算圆圆相对线性扫掠；墙查询复用 SweepWalls，不改变 Dynamic 实体运动权威。
- 有在途弹道时，BallCollisionSystem 在原结算子步内继续细分实际 PhysicsScene2D.Simulate。根据当前双方刚体最大速度，将每段预计目标路程限制为 0.02 格；保存每段真实模拟起止位置，对该段作直线相对扫掠。反弹两侧由多个实际采样片段覆盖，不将整个 1/120 秒折返轨迹合成一条直线。
- 每个名义子步最多 256 个查询细段；超预算显式取消尚在飞行的弹道并增加 SweepBudgetExceededCount，保留先前已捕获命中，剩余物理照常模拟，不继续查询未经细分的路径。所有弹道已命中/到期/撞墙后停止额外细分。SimulationStepCount 仍统计结算子步，PhysicsSliceCount 统计实际 Simulate 次数。
- 控制仅在名义子步开始提交，回调在全部细段内归并；结算仍在原子步边界执行，接触优先于弹道，再按弹道 AttackId 排序，最后超时。细分可能改变 Unity 数值轨迹，不保证与无弹道时逐位相同。
- 0.02 格是预计路程细分阈值，不是任意 Unity 纠偏/冲量/角落约束的严格误差保证。反弹所在单个细段仍用弦近似，临界擦边可有误差；不宣称重建精确反弹时间或任意动态轨迹的连续检测。扩展复杂形状/召唤物时须重新验证。
- Unity 专项通过：静止目标 1000 格/秒弹道；弹道与目标均 480 格/秒的垂直及正面交叉；240 格/秒目标撞右墙时的折返峰值命中（整子步直线会漏检）；返回路径命中及近失与 20 倍细逻辑步参考结果一致。另验证初始重叠、免疫、墙/寿命回收、极端速度预算、暂停/倍速/帧率、致死及重开。
- 报告：WorkspaceRoot/outputs/projectile_validation/projectile-scenarios.txt、unity-results.xml。当前 128 弹道全量命中测试只验证容量和结果不丢失，不作为真机性能结论。

## DEV-008 查询弹道墙反弹（已实现，Unity 待用户验证）

在每个目标运动细段内，弹道按最早墙时刻切分路径，翻转命中墙法线方向上的速度分量，并继续剩余时间。目标线性近似起点同步前移到细段内已经消耗的时间，不把反弹后查询错误地重置到原目标起点。每实例每细段最多 64 次反弹，超过预算停在已查询的墙位置并回收该实例，增加 WallBounceBudgetExceededCount；其他实例继续查询。继承既有目标运动弦近似、256 次物理细分预算和子步承伤顺序，不改变 Dynamic 求解、不创建弹道刚体或新增 Update。反弹次数预算是安全上限，不代表已验证 300 弹道/60 FPS 性能。

## DEV-002 运动实现与证据

以下 DEV-002/003 描述已退出运行路径的旧自管运动与历史验证；DEV-004 保留源码快照和迁移前 Unity 基线，不能冒充新版物理证据。

2026-10-10 已落地双球运动样例；伤害接入见下方 DEV-003，贴附仍待实施：

- LogicCore 使用双精度 PlanarVector、ArenaBounds 与 CollisionGeometry，查询圆墙和圆圆路径上的最早碰撞；相切与正在分离的球不触发反弹。
- GamePlay 的 BallCollisionSystem 统一推进双球。球球先交换法向速度分量，再恢复各自有效速度；若归一化后仍相互接近，退化到各自向外法线。零速球保留方向，不由碰撞恢复速度。
- 同刻先处理 A/B 墙面，再处理球球，必要时继续零时刻墙面约束。角落返回多墙标记；同一球、同一时刻的墙面约束重复求解只累计一次墙撞击。
- 接触通过 IsTouching 与 ContactRound 记录；超过分离容差后才结束接触。初始穿透先纠偏并抑制该重叠关系的新接触计数，不伪造攻击。DEV-003 已接基础互伤批次；通用接触事件数据和墙面能力触发载荷仍待接入。
- BattleSession 采用 1/60 秒步长，每帧最多 8 步、单步最多 64 次碰撞；超长帧最多接收 0.25 秒，额外积压丢弃并累计诊断。碰撞预算耗尽时停在已检测位置，丢弃本步剩余路程，不穿越未检测路径。
- 暂停与后台暂停分别持有状态；切换时清空积压并同步插值状态。ProjectBootstrap 在失焦/后台恢复后舍弃第一帧时长。倍速仅作用于会话时钟，不修改 Unity 全局 timeScale。
- 默认场地 10×10、半径 0.5、移速档 100 对应 3.535534 格/秒，约 4 秒走完整场地对角线；这不是球心内缩区域的对角线标定。出生点为左右球心可行半宽的 75%，方向朝内 ±45°；样例要求场地宽高均大于四倍半径。
- 配置来源暂为 Bootstrap Inspector 的显式原型参数和只读 BattleSettings，尚无正式 JSON 表。会话固定种子，不承诺跨运行时确定性。

## DEV-003 战斗接入

## DEV-004 双球 Dynamic 迁移基线

本节记录 DEV-004 当时的实施和验证基线。2026-10-13 已在 Unity 2022.3.62f3c1 验证两个圆球与矩形静态墙；后续圆形弹道和物理细分增量见上方 DEV-005，多实体注册、组合形状与实体池化仍待实施。

- BattleSession 创建并独占 BallCollisionSystem 的本地 PhysicsScene2D；默认世界不被推进，不改 Physics2D.simulationMode 或全局 timeScale。释放先停用物理根与运动指令，再异步卸载专属场景并释放材质。SceneInit 仍负责会话及 View 装配。
- 默认逻辑步 1/60 秒、每步两个物理子步（1/120 秒，约 8.33 ms）、每帧最多 8 逻辑步/16 子步；2× 通过增加固定步数实现。末步按剩余时限截短，先处理该边界接触，再判超时。
- 每子步：BallMotor 提交控制 → PhysicsScene2D.Simulate → Capture 模拟位置/速度 → 归并接触 → 既有结算器处理互伤。死亡后不再进入下一子步；本子步运动不回滚。100 格/秒致死正碰测试在第一子步结算，最大时间量化误差小于一个子步，不承诺精确 TOI。
- 两球质量 1、gravityScale=0、drag/angularDrag=0、摩擦 0、弹性 1、冻结旋转、Continuous、NeverSleep；刚体插值关闭。位置与速度为 BallMotor 的只读模拟快照，View 仅使用逻辑步前后快照插值，表现 Transform 不带 Collider。
- SetSpeed 修改巡航目标，默认恢复加速度约 7.071 格/秒²；速度方向跟随模拟结果。ApplyImpulse 按质量提交冲量，默认保护 0.15 战斗秒，其间不执行巡航恢复；后续有限加速度恢复。SetStopped 为显式最高优先级，每子步清零速度、拒绝冲量，解除后渐进恢复；SetSpeed(0) 则是渐进减速。未实现冲刺/贴附仲裁。
- BallContactRelay 的 Enter/Stay 只收集稳定身份。双球无序对 (1,2) 在每子步归并为一个事实，不依赖回调顺序；新轮次才进入双向批次，分离超过半径和 + 0.03 格后解除。初始穿透抑制基础攻击，位置纠正交给 Unity；Exit 不直接解除实体关系。
- 墙面按球与边界位标识收集，同球同子步角落按一次撞击计数；墙面默认无伤害。当前仅墙计数，没有能力触发的接触位置/法线载荷。没有弹道来源参与排序，后续来源优先级须另行实现。
- 14 项实际物理场景测试通过，覆盖持续接触、重撞、击退、停止、初始穿透、墙角、免疫、双死、时限、暂停/倍速、隔离、释放、帧率和长运行。8 个种子交替标准/十倍速度，各 1,800 逻辑步，共 28,800 子步；场内容差 0.03 格、球间最小距离 0.95 格（默认直径 1），这是该测试输入下的验收阈值，并非零穿透保证。
- 原始证据：WorkspaceRoot/outputs/dynamic_validation/dynamic/unity-results.xml 与 physics-scenarios.txt；旧 37 用例及真实 Bootstrap 基线共 38 项见 baseline/unity-results.xml。旧运行源码及用例已留档，原自管积分和反弹不在当前运行路径。

## DEV-009 多实体物理（当前增量，待 Unity 验证）

当前代码扩展至最多 64 个实体，物理槽位池复用、身份不复用。接触对与观察标记按固定容量存储；每子步按实体 ID 顺序遍历无序对，独立分配全局递增接触轮次。友方仍参与物理响应，但不产生基础互伤或敌方接触技能。同一对持续接触不追加基础攻击；移除与重新登记清完整接触状态。

每个实际模拟细段保存所有实体的起点/终点；弹道查询按敌方资格和相对路径包围盒保守裁剪，再做圆圆相对扫掠。最早命中按路径时间选目标，相等时按实体 ID。最大目标速度包含召唤物；仍保留 0.02 格路程阈值与每子步 256 细段预算，超预算回收未完成弹道/技能物并诊断。组合形状、任意旋转实体轮廓尚未实现。

吸血关系在边界创建物理约束供下一子步模拟，初始长度取实际距离。减速只改变巡航目标乘数，不直接钉住速度或重复积分；外部冲量请求使关系失效，先解除约束和本来源减速后执行运动。释放关停物理根并卸载专属场景。

联合负载测试已准备同时 300 弹道 + 20 召唤物 + 主球两只，包含分散/密集初始布局、集中生成与持续补充，每档 300 个 60Hz 步。报告测量同步 Advance 与补充生成的 CPU 耗时 P50/P95/P99/max、Gen0 收集次数、Mono 已用内存变化、查询与 Simulate 计数，不是实际渲染帧/GPU、GC 分配字节或真机 60 FPS 结论；当前尚未执行。
